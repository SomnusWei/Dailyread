一、 核心注意要点

字符串清洗与前缀处理
服务器返回的 Base64 字符串可能包含换行符、空格或 Data URL 前缀（如 data:audio/m4a;base64,）。
解码前必须使用正则表达式进行清洗，否则会导致解码失败或音频损坏。

二进制安全解码
使用鸿蒙提供的 util.Base64Helper 的 decodeSync 方法，将 Base64 字符串直接解码为 Uint8Array 字节数组。
严禁使用文本编码（如 UTF-8）参与二进制音频解码。

二进制安全写入文件
音频属于二进制数据，写入本地沙箱文件时必须使用二进制模式。
将 Uint8Array 的 .buffer 属性传给 fs.writeSync 进行写入。
高危反模式：绝对不要将字节数组先转为普通字符串再写入，这会导致换行符转换或 BOM 字节污染，使 m4a 文件头损坏。

本地文件路径规范
文件写入沙箱（如 cacheDir）后，传给 AVPlayer 的路径必须加上 file:// 前缀，否则播放器无法识别本地资源。

临时文件生命周期管理
每次拉取新音频前，建议先检查并删除本地同名临时文件，防止文件被追加或读取到脏数据。

AVPlayer 状态机监听
AVPlayer 基于状态机运行。必须在设置资源前注册 stateChange 监听。
当状态变为 initialized 时调用 prepare()，当状态变为 prepared 时才能调用 play()。

二、 权限与后台配置

基础播放权限（当前场景必备）
网络权限 (ohos.permission.INTERNET)：如果 audiobase64 字段是通过网络接口从服务器拉取的，必须申请此权限。

后台播放权限（如需支持息屏/切后台播放）
如果音频需要在应用退至后台或锁屏时继续播放，必须补齐以下三项配置，缺一不可：
后台保活权限 (ohos.permission.KEEP_BACKGROUND_RUNNING)：申请后台长时任务权限。
媒体控制权限 (ohos.permission.MEDIA_CONTROL)：用于 AVSession 与系统播控中心交互。
后台模式声明 (audioPlayback)：在 module.json5 的 abilities 节点中，必须声明 "backgroundModes": ["audioPlayback"]。

module.json5 配置示例
{
  "module": {
    "requestPermissions": [
      { "name": "ohos.permission.INTERNET" },
      { "name": "ohos.permission.KEEP_BACKGROUND_RUNNING" },
      { "name": "ohos.permission.MEDIA_CONTROL" }
    ],
    "abilities": [
      {
        "name": "EntryAbility",
        "backgroundModes": ["audioPlayback"]
      }
    ]
  }
}

三、 ArkTS 完整示例代码

以下代码包含了 Base64 处理、AVPlayer 状态机控制及 AVSession 后台保活的完整逻辑：

import { media } from '@kit.MediaKit';
import { util } from '@kit.ArkTS';
import { fs } from '@kit.CoreFileKit';
import { common } from '@kit.AbilityKit';
import { BusinessError } from '@kit.BasicServicesKit';
import { AVSession, AVSessionManager } from '@kit.AVSessionKit';
import { backgroundTaskManager } from '@kit.BackgroundTasksKit';

export class AudioPlayerManager {
  private avPlayer: media.AVPlayer | null = null;
  private avSession: AVSession | null = null;
  private context: common.UIAbilityContext;

  constructor(context: common.UIAbilityContext) {
    this.context = context;
  }

  /**
   核心方法：处理 Base64 并自动播放
   */
  public async playBase64Audio(base64Str: string): Promise<void> {
    try {
      // 1. 字符串清洗：去除 Data URL 前缀、换行符和空格
      const cleanBase64 = base64Str.replace(/^data:audio/[a-z0-9]+;base64,/, '')
                                   .replace(/[rns]/g, '');

      // 2. 二进制安全解码
      const base64Helper = new util.Base64Helper();
      const uint8Array = base64Helper.decodeSync(cleanBase64);

      // 3. 准备本地临时文件路径并清理旧文件
      const tempFilePath = {this.context.cacheDir}/temp_audio.m4a;
      if (fs.accessSync(tempFilePath)) {
        fs.unlinkSync(tempFilePath); // 删除旧文件防止脏数据
      }

      // 4. 二进制安全写入文件
      const file = fs.openSync(tempFilePath, fs.OpenMode.CREATE | fs.OpenMode.WRITE_ONLY);
      fs.writeSync(file.fd, uint8Array.buffer);
      fs.closeSync(file);

      // 5. 初始化播放器并自动播放
      await this.initAndPlay(file://{tempFilePath});

    } catch (err) {
      const error = err as BusinessError;
      console.error(Base64 音频处理失败: {error.message});
    }
  }

  /**
   初始化播放器并监听状态机
   */
  private async initAndPlay(filePath: string): Promise<void> {
    // 释放旧实例
    if (this.avPlayer) {
      await this.avPlayer.release();
    }

    this.avPlayer = await media.createAVPlayer();

    // 【关键】必须在设置资源前注册状态机监听
    this.avPlayer.on('stateChange', async (state: string) => {
      switch (state) {
        case 'initialized':
          await this.avPlayer?.prepare();
          break;
        case 'prepared':
          await this.avPlayer?.play();
          console.info('音频自动播放成功');
          // 播放时申请长时任务
          this.startBackgroundTask();
          break;
        case 'completed':
          console.info('音频播放完成');
          this.stopBackgroundTask();
          break;
      }
    });

    // 错误监听
    this.avPlayer.on('error', (err: BusinessError) => {
      console.error(AVPlayer 错误: {err.code}, ${err.message});
      this.avPlayer?.reset();
    });

    // 设置本地文件路径，触发 initialized 状态
    this.avPlayer.url = filePath;
  }

  /**
   申请后台长时任务 (AUDIO_PLAYBACK)
   */
  private startBackgroundTask() {
    try {
      backgroundTaskManager.startBackgroundRunning(
        backgroundTaskManager.BackgroundMode.AUDIO_PLAYBACK,
        'audioPlaybackTask',
        (err) => {
          if (err) console.error('申请长时任务失败:', err.message);
        }
      );
    } catch (e) {
      console.error('长时任务异常:', e);
    }
  }

  /**
   取消后台长时任务
   */
  private stopBackgroundTask() {
    try {
      backgroundTaskManager.stopBackgroundRunning(
        'audioPlaybackTask',
        (err) => {
          if (err) console.error('取消长时任务失败:', err.message);
        }
      );
    } catch (e) {
      console.error('取消长时任务异常:', e);
    }
  }

  // 页面销毁时释放资源
  public async destroy() {
    if (this.avPlayer) {
      await this.avPlayer.release();
      this.avPlayer = null;
    }
    this.stopBackgroundTask();
  }
}

四、 补充说明

内存优化：Base64 解码为二进制数组会占用一定内存，如果音频文件过大，建议评估是否需要改用流式下载（HTTP URL 直接播放）以减轻内存压力。
音频焦点管理：如果应用中存在其他音频播放场景，建议主动监听音频焦点事件（audioInterrupt），根据业务逻辑做出暂停或降低音量等处理，避免多音频混音冲突。
资源释放：音频播放完毕或不再需要播放时，务必调用 release() 方法释放 AVPlayer 资源，避免造成内存泄漏或音频焦点被持续占用。
